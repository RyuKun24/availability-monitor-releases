# Release Checklist & Workflow Enforcement

You are assisting with the Availability Monitor project. This project has a strict release workflow that MUST be followed.

## Release Workflow (NON-NEGOTIABLE)

Whenever a feature is "complete" and ready for release:

### Step 1: Verify Branch
```
Current branch must be: feature/something
NOT: main
```

### Step 2: Verify Version Sync
```
pyproject.toml:          version = "X.Y.Z"
electron/package.json:   "version": "X.Y.Z"

⚠️  These MUST match exactly, or build will fail
```

### Step 3: Create Tag
```bash
git tag vX.Y.Z
git push origin feature/branch-name --tags
```

### Step 4: Monitor Build
```
1. Go to: https://github.com/RyuKun24/availability-change-alert-sender/actions
2. Wait for "Build and Release" workflow
3. Expected result: ✅ SUCCESS
   If ❌ FAILED: Read error, fix, bump version, retry
```

### Step 5: Verify Release
```
1. Go to: https://github.com/RyuKun24/availability-change-alert-sender/releases
2. Release vX.Y.Z should exist
3. Files should include:
   - availability_monitor.exe
   - Availability Monitor Setup *.exe
   - Availability Monitor-*.exe
```

### Step 6: Merge to Main (if success)
```bash
git checkout main
git merge feature/branch-name
git push origin main
```

## Your Duties

Before marking a release "done", you MUST:

- [ ] Verify feature branch (not main)
- [ ] Check version sync (both files)
- [ ] Create and push tag
- [ ] Wait for GitHub Actions ✅ SUCCESS
- [ ] Verify release files on GitHub
- [ ] Only THEN declare feature complete

## Common Failures & Fixes

| Error | Cause | Fix |
|-------|-------|-----|
| Version mismatch | pyproject.toml ≠ package.json | Sync both, bump to v0.1.(Z+1), retry |
| PowerShell parse error | Unicode or quote issues | Fix script, bump version, retry |
| Build timeout | Dependencies slow | Retry with v0.1.(Z+1) |
| Tag already exists | Duplicate tag | Delete both tags, bump version, create new |

## When User Says...

| User Says | You Do |
|-----------|--------|
| "Ready to release" | Verify version sync, create tag, push, monitor build |
| "Build failed" | Read error, suggest fix, help recover with bumped version |
| "Is it done?" | Check GitHub Actions + releases page, report SUCCESS or FAILED |
| "New feature" | Create feature branch, explain workflow |
| "Merge to main" | Ensure SUCCESS first, then merge |
